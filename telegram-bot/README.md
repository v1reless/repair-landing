# Telegram-бот для заявок «МастерДом»

Локальный Node.js-сервер, который:

- отдаёт лендинг из родительской папки;
- принимает заявки на `POST /api/lead`;
- проверяет данные;
- отправляет сообщение в Telegram через Bot API.

Токен бота хранится только в `.env` на сервере и не попадает в браузер.

## 1. Создать бота

1. Откройте Telegram и найдите **@BotFather**.
2. Отправьте команду `/newbot`.
3. Имя бота, например: `МастерДом Заявки`.
4. Username должен заканчиваться на `bot`, например: `masterdom_leads_bot`.
5. Скопируйте токен вида `123456789:AA...`.
6. Откройте своего нового бота и нажмите **Start**.

## 2. Заполнить `.env`

В папке `telegram-bot` уже есть файл `.env`. Откройте его:

```powershell
notepad D:\projects\repair-landing\telegram-bot\.env
```

Вставьте токен:

```env
BOT_TOKEN=123456789:AA...
CHAT_ID=
PORT=8787
```

`CHAT_ID` пока оставьте пустым.

## 3. Узнать CHAT_ID

В PowerShell:

```powershell
cd D:\projects\repair-landing\telegram-bot
npm run chat-id
```

Если скрипт пишет, что сообщений нет:

1. Откройте бота в Telegram.
2. Нажмите **Start** или отправьте `/start`.
3. Запустите `npm run chat-id` снова.

Скрипт покажет:

```text
CHAT_ID=123456789 — Ваше Имя
```

Вставьте этот ID в `.env`:

```env
CHAT_ID=123456789
```

## 4. Запустить сервер

```powershell
cd D:\projects\repair-landing\telegram-bot
npm start
```

Откройте:

```text
http://127.0.0.1:8787/
```

Заполните форму на лендинге. Сообщение должно прийти в Telegram.

## 5. Проверка без формы

В отдельном терминале, пока сервер запущен:

```powershell
cd D:\projects\repair-landing\telegram-bot
npm test
```

Скрипт отправит одну тестовую заявку.

## Проверка без Telegram

Можно проверить всю цепочку, не отправляя сообщение в Telegram:

```powershell
$env:DRY_RUN='1'
npm start
```

В этом режиме сервер выведет текст заявки в консоль. В Telegram ничего не уйдёт.

Чтобы вернуться в обычный режим, перезапустите терминал или выполните:

```powershell
$env:DRY_RUN='0'
npm start
```

## Как это работает

```text
Форма на лендинге
        ↓ POST /api/lead
Локальный Node.js-сервер
        ↓ Bot API
Telegram
```

Сервер сам подставляет `/api/lead` в HTML через meta-тег. На GitHub Pages этот тег остаётся пустым, поэтому там форма работает в демо-режиме.

## Если что-то не работает

### `BOT_TOKEN не найден`

Проверьте, что файл `telegram-bot/.env` существует и в нём заполнен `BOT_TOKEN`.

### `Unauthorized`

Токен неверный или скопирован не полностью. Создайте токен заново через BotFather.

### `chat not found`

Проверьте `CHAT_ID`. Обязательно нажмите **Start** у бота — без этого Telegram не разрешает писать вам.

### `409 Conflict`

У бота установлен webhook. Для локального теста его нужно удалить. Если бот раньше не использовался, этой ошибки быть не должно.

### `Порт 8787 занят`

Остановите другой сервер или измените порт в `.env`:

```env
PORT=8788
```

После этого открывайте `http://127.0.0.1:8788/`. Менять `script.js` не нужно.

### В консоли кракозябры вместо русских букв

Это кодировка консоли Windows, на работу бота не влияет. Можно переключить кодировку:

```powershell
chcp 65001
npm start
```

## Публикация

GitHub Pages — это статический хостинг. Node.js-сервер на нём не работает.

Для боевого варианта нужен серверный хостинг:

- Vercel;
- Render;
- Railway;
- обычный VPS.

Токен и `CHAT_ID` там задаются через переменные окружения хостинга. В браузерный код их добавлять нельзя.

## Безопасность

- Не коммитьте `.env`.
- Не вставляйте токен в `script.js`, HTML или GitHub.
- Не отправляйте токен в чат.
- Для публичного сервера добавьте ограничение частоты запросов и защиту от спама.
